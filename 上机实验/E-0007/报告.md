# E-0007　芯片怎样排队、处理器时间怎样分：量常数、检验模型、量算出来的做法

这份报告里用到的叫法：

- 新驱动：`worktrees/openwrt-nss-adaptation-workrepo` 里的 `ipq807x-eth`。正式的驱动：代码树里新驱动目录的源码原样编出来的模块。
- 模型：第四步设计文件 `各阶段设计/阶段一/4-多环和日常功能.md` 第十节。下面写"式 4""式 10"，指那一节里标了号的式子。
- 一窗：先把负载起起来，等它稳，叫实验用的模块记若干秒，停负载，读回。模块到时间自己停，不靠串口上的命令掐时间。
- 收包环、空缓冲区环、发包环、发完环：EDMA（主机和 PPE 之间收发包的那一块硬件）的四种环。收"发完"：硬件把发出去的包登记在发完环上，驱动把登记收回来、把包释放。
- 缓冲管理：PPE 里记每个口占着多少缓冲、占多了就叫这个口的对端先别发的那一部分。记账口：缓冲管理里的 15 个"口"，0 到 7 号记主机发的包，8 到 13 号是 1 到 6 号物理口（12 号是 `wan` 收进来的，11 号是 `lan2` 收进来的，10 号是 `lan3` 收进来的），14 号是内部的。
- 暂停帧：以太网口叫对端先停一会儿的帧。

## 1. 问题、依据和判据

### 1.1 这个实验要回答的事

E-0006 留下两条负面的判据，原因没有量到：路由器一边转发、一边自己往 `wan` 发时转发只有 161 到 449 兆比特每秒，`wan` 和 `lan2` 自己发暂停帧（E-0006 判据 4-4）；两个千兆口被压住时主机往 `wan` 发的从三千多兆掉到几十到二百多兆（E-0006 判据 4-7 的头一半）。这个实验分三段回答：

1. 量常数。模型里芯片这一头的常数（交货的上限、叫停和放开的门限、哪个记账口触发哪个口的暂停帧、一份缓冲什么时候还回去、中断延时寄存器的单位、"发完"出现要多久）和软件这一头的系数（一轮收包、一轮收"发完"各样活各花多少处理器时间，线程等多久才排上，观测本身花多少）。
2. 检验模型。用量到的常数算 E-0006 那两组负载的读数，和重放时量到的比；再留一种不参加拟合的配法，先算后量。
3. 量算出来的做法。用量到的常数算出每一种做法能同时撑住多少转发和多少本机发送，取最好的一种，做成实验用的模块的一种配法，重放同一组负载。

不做这个实验，设计第十节里的式子只有形式、没有数，算不出哪一种做法最好，决定-005（收"发完"的轮询放在线程里还是软中断里）也定不了。

另外重读 E-0006 的判据 4-11（硬件报错的中断带着不认得的状态进来时，内核记录的行数），判法照设计第九节判据表第 11 条的原话。

### 1.2 问得了什么，问不了什么

- 问得了：这块硬件在这一种接线下的常数；驱动和内核在这几种负载下每类活的开销；每一种可以调的量换了以后的变化。
- 问不了：转发的两头里有一头是千兆口（`lan2`、`lan3`），1500 字节的帧时转发最多到千兆的线速（每秒 8.1 万帧），撑不到处理器的上限；所以处理器这一头的上限用小包量（千兆下每秒最多 148.8 万帧）。`wan` 是万兆，主机发小包发不到万兆的线速（每秒 1488 万帧）：主机发到头芯片还没有到顶时，量到的只是交货上限的下界，照实写。
- 问不了：带固件时的情形。

### 1.3 接线和地址

线不换：`wan` 接主机的 `eno1`（主机这一头是桥 `br-lan`），`lan2` 接主机的 `eno2`，`lan3` 接主机的 USB 网卡。地址和 E-0006 一样：`eno2` 192.168.1.10 对路由器 192.168.1.1；USB 网卡 192.168.11.10 对路由器 192.168.11.1；`br-lan` 192.168.13.10 对路由器的 `wan` 192.168.13.1。穿过路由器的转发照 E-0004 的三种走法，把主机的一块网卡放进网络命名空间：`lan2` 进 `wan` 出、`wan` 进 `lan2` 出（这两种经过路由和地址转换），`lan2` 进 `lan3` 出（经过路由器的软件桥）。

主机这一头：NetworkManager 里除了 Wi-Fi 以外的设置可以改，收工时全部改回去并回读；Wi-Fi 不碰。BMC 的网卡、主机的路由不碰。地址（MAC）的数值不显示、不写进任何文件。路由器只做内存引导。

### 1.4 被量的东西

**镜像**：E-0006 最后交的那一个，sha256 `dce0781bba59eb44635bc1bf6ec1e8e94d06b0c8d3ae7f4b38beb65900418f06`，里面带的正式的模块 md5 `f94f183c0b746ccc39b6c47307eaeeb5`。这一次没有重编镜像。

**实验用的模块 `variant-e7.ko`**（和正式的驱动的差异在 `variant-e7.diff`）。它是在代码树的临时目录里当成内核以外的模块编的，正式的驱动目录没有动；加载它以后内核会记一个"加载过内核以外的模块"的标记。不带参数、不开记录时，它做的事和正式的驱动一样，只多两处：每一轮轮询多一次"要不要记"的判断，读写环的寄存器多一层函数。它有三样东西：

1. 自己记的。
   - 每一轮收包、每一轮收"发完"：开始的时刻、用时、做了几格、几帧里转发的、交本机的、应答的各几个、补了几页、逐格找页走了几格、进来和出去时环上的生产位置和消费位置、离叫它的中断隔了多久、离上一轮隔了多久、这一轮里顺带发了几个包；收"发完"的一轮另记叫醒了几条发送队列、上一轮以后这个核心在软中断里发了几个本机的包。
   - 每个核心：硬中断三类、软中断十类、线程七类各用了多少时间（挂在内核的调度和中断的观测点上直接累加）。
   - 每个轮询的线程：被叫醒以后等了多久才跑、被换下去以后等了多久才又跑。发包的进程：等了多久才排上处理器。
   - 每个发出去的包：是在哪一类上下文里发的。
   - 每条发送队列：窗里往发包环放了几个包、被停了几次、被叫醒了几次、排队规则丢了几个；压着多少字节没有报"发完"、字节上限、排队规则里积着几个包（这三样跟着定时采样器一起读）。
2. 两个读寄存器的工具，都不过新驱动读写寄存器的那把锁。定时采样器：一个定时的中断里每隔一段读一遍 97 个寄存器（15 个记账口的"占着多少"和状态字、共用的那一组用掉多少、叫停以后占着多少、主机四条队列积着多少、四种环的位置、三个口收发的暂停帧数、三个口的 MAC 收到和发出的帧数、缓冲管理丢的帧数），读一遍量到 21 到 26 微秒。快读器：一个线程在一个核心上不停地读最多 8 个寄存器，把每一次变化和时刻记下来，读一圈不到一微秒，一次最多读 5 秒。
3. 可以换的做法。加载时的参数：

| 参数 | 和正式的驱动差在哪里 |
|---|---|
| `exp_tx_thread=1` | 收"发完"的轮询放进线程 |
| `exp_rx_softirq=1` | 收包的轮询放在软中断里，不进线程 |
| `exp_combined=1` 或 `2` | 第 n 个收包环和第 n 个发完环合成一个轮询，两个中断都叫它；1 是先收"发完"，2 是先收包 |
| `exp_rx_weight`、`exp_tx_weight` | 一轮收包、一轮收"发完"最多做多少（正式的驱动是 64） |
| `exp_cmpl_shift` | 第 q 条发送队列的"发完"报到第 q 加这个数个发完环（正式的驱动是 0：在发它的那个核心上处理） |
| `exp_rx_ring`、`exp_tx_ring`、`exp_txcmpl_ring` | 三种环的长度 |
| `exp_bm_react`、`exp_bm_ceiling`、`exp_bm_weight`、`exp_bm_resume`、`exp_bm_group` | 物理口的记账口的门限寄存器里的几栏、共用的那一组的份数 |
| `exp_no_fc=1` | 主机这一侧的 8 个记账口不开流控 |
| `exp_raw_io=1` | 轮询和发送里读写环的寄存器不过共用的那把锁 |
| `exp_page_idx=1` | 页的号记在页的开头（硬件不写的地方），不记在包头里 |
| `exp_sync_len` | 页还回页池时缓存同步多长（正式的驱动是整个缓冲 3712 字节） |
| `exp_rx_hardirq=1` | 收包环上的活（取帧、补缓冲）直接在硬中断的处理函数里做，一次中断最多做 `exp_hardirq_budget` 格（默认 256）；取出来的帧排在驱动自己的一个队列里，收包的轮询只把它们交给协议栈；队列里到了 `exp_rx_swq` 个（默认 8192）就不再从环里取、把中断关上，等轮询把队列做到一半以下再打开。内核把包往协议栈上交的函数不许在硬中断里调，所以协议栈的活仍然在轮询里 |
| `exp_tx_hardirq=1` | 收"发完"直接在硬中断的处理函数里做，一次中断最多做 `exp_hardirq_budget` 条 |
| `exp_defer_irqs`、`exp_gro_flush_us` | 一轮轮询做完、环上没有东西了，先不开中断，隔 `exp_gro_flush_us` 微秒内核再叫它轮一次，连着 `exp_defer_irqs` 次都没有东西才开中断（内核现成的机制）。正式的驱动是做完就开中断 |
| `exp_cpu_q_ceiling` | PPE 里通主机的四条队列各自最多积多少份缓冲（正式的驱动写的是 400）。调到物理口叫停的门限以下，哪个收包环满了，芯片只丢排给这个环的帧，不叫整个口的对端停。带这个参数时同时把这四条队列的"对开着流控的口进来的帧也照门限丢"那一位（高通的库里叫 `ac_cfg_force_ac_en`，队列配置字的第 2 位）打开：不开这一位，从开着流控的口进来的帧不受队列的门限管，队列照样积过门限 |

运行时可写的：`exp_fill_every`（写 n 时每 n 轮收包才把这几轮欠的缓冲一起补上，让一轮补的页数和格数不成比例）、`exp_tx_scan_extra`（一轮收"发完"把端口表多空扫几遍）、`exp_tx_budget`（一轮收"发完"最多做几条）、`exp_rx_drop_port`（目的端口在这个数起 100 个以内的 UDP 帧，换好缓冲以后就丢）、`exp_rx_delay_us`（每一轮收包先空等若干微秒）、`exp_fill_lag`（少告诉硬件若干个新缓冲）、`exp_cons_lag`（少告诉硬件若干格已经取走）；诊断目录的命令 `mod`（改中断延时寄存器）、`ictl`（改中断控制寄存器）、`prio`（改轮询的线程的优先级）、`stall`（四个核心关着中断空转若干秒，到时间自己结束）。

**`variant-e6b.ko`**：E-0006 的实验用的模块，照 E-0006 文件夹里的 `variant-e6b.diff` 重新编的（编法和 `variant-e7.ko` 一样），只给重读 E-0006 判据 4-11 用。

**发包的工具**：主机上内核自带的 `pktgen`（定速发 UDP 帧，不经过协议栈）和 `iperf3`；路由器上的 `iperf3`，和照同一份内核源码编的 `pktgen.ko`（上机时传到路由器的内存里）。读每队列统计的工具（python 和内核源码树里的 `ynl`）同 E-0006，也是上机时传上去。

每一窗读回来的：模块记的每个核心各类时间、每个环的合计和直方图、每轮的记录（压成回归用的和、照格数分档的平均、几个分位数）、定时采样的压成每个寄存器的几个数、负载自己报的数、路由器三个口前后的收发数和路由器自己的 TCP 计数、主机三块网卡每 50 毫秒的收发帧数。主机和路由器的钟：每一窗的负载起来以前、停了以后，路由器闲着的时候主机各发 6 个带号的 UDP 包，模块记下收到的时刻，两头的差的最小值当钟差，最大减最小当对钟的误差；两件事隔得比这个误差还近，先后记成不知道。

几个数放在一起比，取的是同一段时间：负载跑的时间比模块记的那一段长，所以"窗里"的数只用三处。模块自己数的（它只在窗里数）；定时采样器在窗的两头读到的计数器相减（MAC 收发的帧数、暂停帧数、各环的位置，误差不超过一个采样间隔）；主机网卡每 10 毫秒读一次的累计帧数，照对好的钟插到窗的两头再相减（误差是对钟的误差加 10 毫秒，乘当时的速率；有的网卡的计数隔一段才更新一次，脚本把它多久更新一次量出来，两头各可能差一次更新的量，一起折进误差）。发包工具、`iperf3` 自己报的总数是整段负载的，摘要里单独标着"不是窗里的"，不和窗里的数比。每一窗主机网卡的序列存在工作文件夹里。

重复和次序：`rxdrop`、`txonly`、`fwd`、`mix` 靠速度的档数当重复（每一张表十几到二十几窗进同一个回归）；`fwdmix` 三窗；`jam` 压和不压交替各两窗；`holdout` 三窗；`knob` 每种配法四窗，头尾各做一遍不换任何东西的当基线，看漂没漂。先做收了就丢和只发（负载最简单，诊断代码有毛病先露出来），再做转发，最后做混合的。

要换加载时的参数的配法，每一种卸载、加载一次；运行时可写的不用。在正式的驱动的配法（不带参数）上做全部的表；在 `exp_tx_thread=1`（E-0006 的另一种配法）上做 `txonly-pktgen`、`txonly-iperf`、`mix-route-up`、`mix-route-down`、`fwdmix-route-up`、`fwdmix-route-down`、`jam`。

别的可以调的量各做 `knob` 一张，先看每类活的开销是降是升：`exp_raw_io=1`；`exp_page_idx=1`；`exp_sync_len=256`；`exp_rx_softirq=1`；`exp_combined=1`、`2`；`exp_cmpl_shift=1`、`2`；`exp_rx_weight` 16 和 256；`exp_tx_budget` 16；`exp_rx_hardirq=1`；`exp_tx_hardirq=1`；两样一起；收包线程的优先级（`prio rx -20`、`prio rx 100`）；内核的合并关掉；中断延时换两个数；收包环 512 和 4096 格；物理口叫停的上限 `exp_bm_ceiling` 换两个数。开销降了的那几样叠在一起，再和每一种"放在哪里做"的配法（线程、软中断、硬中断、合成一个轮询、线程的优先级）配起来，各做 `mix-route-up`、`mix-route-down` 两张得到整条边界。

拟合：每轮的用时对各列做回归（脚本的 `fit` 阶段）；回归以外的分析（门限、单位、等待的分布、边界）由写这份报告第 1 节的会话照结果摘要里的数算，算法和算出来的数写进第 4 节和设计第十节。

### 1.8 候选的配法，和事先算的数

这一小节是上机开始以后、候选的配法量以前写的，是写这一节的会话定的。它用到的读数只有正式的驱动的配法和 1.5 里列的那几种单样的配法的（结果摘要里名字是"正式-"和"五-"开头的窗）；候选的配法这时一窗都还没有量。

**处理器的频率。** 路由器上处理器的频率是自动调的（调法 `schedutil`，四个核心共用一个时钟，1017600 到 2208000 千赫）。从量候选起，每一窗在负载起来以前、停了以后各读一次各个频率各待了多久；另有一张"频率固定在最高"的四窗对照。

**事先算用的单价。** 拿正式的驱动的配法上四个核心合计忙到 250% 以上的窗里没有顶满的核心（154 个"核心乘窗"），把每个核心忙的时间对这个核心上各类活的量做回归，不带常数项，得到（微秒，后面是标准误差）：

| 一份活 | 单价 |
|---|---|
| 转发一帧，`lan2` 进 `wan` 出 | 3.52 ± 0.45 |
| 转发一帧，`wan` 进 `lan2` 出 | 8.96 ± 0.45 |
| 收包的轮询跑一轮（和这一轮做几格无关的那一份：中断、叫醒线程、轮询函数固定的一份、把合并好的包交出去、睡下） | 43.3 ± 1.8 |
| 收一条"发完" | 1.48 ± 0.30 |
| 发一个本机的包（进程、协议栈、驱动的发送一起） | 9.56 ± 0.68 |
| 交给本机一帧（只算收包这一头，不算收它的进程） | 3.99 ± 1.08 |
| 一个应答 | 16.5 ± 11.5（标准误差太大，没有量出来） |

这组单价算回它自己用的那 154 个"核心乘窗"，差在 8 个百分点以内的只占 61%，所以它是粗的；下面的数照 7-7、7-9 的容差去对，对不上照那两条的"负面时照什么做"办。

**每一档本机实际速率上转发最多到多少（事先算的）。** 条件：四个核心的时间用完（式 16 取等号）；本机发的每兆比特每秒是 82.65 个包；转发的流在四个收包环上分得匀。分得不匀时，分得最多的那个环先顶满，整个口被暂停帧拖住，转发要再乘"四分之一除以最多的那个环占的份"。

- 收包的线程排在发包的进程前面、轮询做完就开中断（`prio rx -20`，或者 `prio rx 100`）：一轮做几格由负载定，事先算不出，预计和 `prio rx 100` 已经量到的边界一样：`lan2` 进 `wan` 出（1601 兆，每秒 42.3 万帧）、（2547 兆，27.9 万）、（3252 兆，11.9 万）；`wan` 进 `lan2` 出（1589 兆，24.4 万）、（2932 兆，13.7 万）。
- 再加"做完先不开中断、隔 τ 再轮一次"（`exp_defer_irqs=2`、`exp_gro_flush_us=τ`）：每个环每秒轮 1/τ 次，四个环轮询固定的一份合计是 4 × 43.3 微秒 ÷ τ 个核心（τ 是 1000 微秒时 0.173 个，200 微秒时 0.866 个）。转发最多 =（4 − 本机每秒的包数 × 10.06 微秒 − 轮询固定的一份）÷ 每帧的单价；每帧的单价 `lan2` 进 `wan` 出是 3.52 + 1.48 = 5.00 微秒，`wan` 进 `lan2` 出是 8.96 + 1.48 = 10.44 微秒；10.06 是 9.56 加上每个包摊到的应答。

| 本机实际发出（兆比特每秒） | τ = 1000 微秒，`lan2` 进 `wan` 出 | τ = 1000 微秒，`wan` 进 `lan2` 出 | τ = 200 微秒，`lan2` 进 `wan` 出 | 正式的驱动的配法量到的（两种走法） |
|---|---|---|---|---|
| 535 | 每秒 67.6 万帧（超过单独转发量到的 55.6 万到 58.6 万，以单独转发量到的为上限） | 32.4 万 | 53.8 万 | 55.7 万、24.1 万 |
| 1605 | 49.8 万 | 23.9 万 | 36.0 万 | 36.3 万、18.4 万 |
| 2500 | 35.0 万 | 16.8 万 | 21.1 万 | 没有落在这一档的窗 |
| 3250 | 22.5 万 | 10.8 万 | 8.6 万 | 10.2 万、6.5 万 |
| 4000 | 10.0 万 | 4.8 万 | 算出来是负的：这一档撑不住 | 4.4 万（4263 兆）、没有 |

所以事先算出来最好的是：收包的线程排在发包的进程前面，加 τ = 1000 微秒。τ = 200 微秒在本机发得多的那几档比正式的驱动的配法还差。

- 再加"满了的环只丢它自己的"（`exp_cpu_q_ceiling=64`）：流分得不匀时，转发不再被分得最多的那个环拖住，等于每个环各自"要的和撑得住的里小的那个"加起来；预计 `wan`、`lan2` 自己发的暂停帧是 0，丢的帧记在通主机的队列上。

**留着不参加拟合的负载（`holdout`）在正式的驱动的配法上，事先算的。** 负载要的：`wan` 进 `lan2` 出每秒 6.38 万帧（512 字节）；路由器往 `wan` 发 64 条各限 24 兆的 TCP，照帧的字节算是 1605 兆比特每秒；主机往路由器的 `wan` 发 16 条各限 50 兆的 TCP，照帧的字节算是 836 兆比特每秒（每秒 6.9 万帧）。照上面的单价加起来是 3.4 个核心（转发 0.57，收包的轮询每秒 1.15 万轮 0.50，收"发完"0.34，发本机的包 1.27，交本机 0.28，收它的进程 0.44——这一样单价表里没有，取"主机往路由器发 UDP"那一张表里别的线程每帧 6.4 微秒），不到 4 个；每个环每秒 3.5 万帧，收包的线程被换下去 20 毫秒也只积 700 格，不到 2048 格。所以预计三样都照要的到：转发每秒 6.38 万帧，路由器往 `wan` 1605 兆，主机往路由器 836 兆，路由器的口不发暂停帧。四个核心平均：收包的线程 35%，发包的进程和它带出的软中断 32%，收"发完"的软中断 8.5%，别的线程 11%，空闲 15%。

**量候选的那一程做什么。** 每一种配法做 `knob` 一张；标了"边界"的再做 `mix-route-up`、`mix-route-down` 两张。

| 名字 | 配法 | 做哪几张 |
|---|---|---|
| 甲 | `prio rx -20` | 边界 |
| 乙 | `prio rx -20`，`exp_defer_irqs=2 exp_gro_flush_us=200`，`exp_rx_ring=4096` | `knob`、边界 |
| 丙 | `prio rx -20`，`exp_defer_irqs=2 exp_gro_flush_us=1000`，`exp_rx_ring=4096` | `knob`、边界 |
| 丁 | 丙再加 `exp_cpu_q_ceiling=64` | `knob`、边界 |
| 戊 | `prio rx 100`，`exp_defer_irqs=2 exp_gro_flush_us=1000`，`exp_rx_ring=4096` | `knob` |
| 己 | `exp_cpu_q_ceiling=64`（别的同正式的驱动） | `knob` |
| 庚 | `exp_rx_hardirq=1`，控制台的记录开到最细 | `knob` 里"转发小包加路由器往 wan 发"一窗；没有崩再做其余三窗 |

另外在正式的驱动的配法上做 `holdout` 三窗，和 `replay` 压两个口一遍（上一遍模块记的那一窗没有读成）。

### 1.9 候选定成哪一种，和在它上面事先算的数

这一小节是 1.8 的七种配法量完以后、候选的最后一程量以前写的，是写这一节的会话定的。

**候选定成"收包的线程排在发包的进程前面"（`prio rx -20`：收包的四个线程的优先级调到普通线程里最高），别的同正式的驱动。** 依据是量到的边界（本机实际发出多少兆比特每秒，转发每秒到多少万帧；一档里取最大的）：

| 走法 | 这种配法 | 正式的驱动的配法 |
|---|---|---|
| `lan2` 进 `wan` 出 | (70, 66.1) (535, 47.1) (1606, 45.5) (3186, 21.3) (3534, 16.2) (4034, 9.1) | (70, 52.6) (535, 55.7) (1605, 36.3) (2985, 2.6) (3232, 10.2) (4263, 4.4) |
| `wan` 进 `lan2` 出 | (70, 35.3) (536, 32.5) (1619, 26.1) (2962, 14.4) (3026, 13.6) (3519, 10.1) | (70, 27.8) (535, 24.1) (1644, 18.4) (2901, 6.3) (3206, 6.5) (3571, 6.1) |

1.8 里别的几种没有一档比它高出百分之五：加"做完先不开中断"的两种（τ 是 200、1000 微秒）在本机 3100 兆上下是 19.0 万、16.4 万；再加"满了的环只丢它自己的"是 11.1 万，而且这一种有 6 窗的 `iperf3` 连不上或者中途断了；收包的线程用实时优先级是 11.9 万。

1.8 事先算的和量到的对不上的两处，照实记：τ 是 1000 微秒那一种在本机 3250 兆时算的是每秒 22.5 万帧，量到（3113 兆）16.4 万，少百分之二十七；`prio rx -20` 算的是"和实时优先级量到的一样"（3252 兆，11.9 万），量到（3186 兆）21.3 万，多百分之七十九。所以 1.8 的算法缺一项：收包的轮询每秒跑几轮不是只由"隔多久轮一次"定的，还由收包的线程用哪一种优先级定——实时优先级一有中断就抢进来、一轮只做一两格，普通线程里最高的优先级要等正在跑的进程让出来、一轮做十几到几十格。

**补了这一项以后在候选上事先算的。** 候选上量到轮询固定的一份合计约 0.3 个核心，转发最多 =（4 − 0.3 − 本机每秒的包数 × 10.06 微秒）÷ 每帧的单价（5.00、10.44 微秒）：

| 本机实际发出（兆比特每秒） | `lan2` 进 `wan` 出 | `wan` 进 `lan2` 出 |
|---|---|---|
| 535 | 每秒 65.1 万帧（以单独转发量到的为上限） | 31.2 万 |
| 1605 | 47.3 万 | 22.7 万 |
| 3200 | 20.8 万 | 10.0 万 |
| 3500 | 15.8 万 | 7.6 万 |
| 4000 | 7.5 万 | 3.6 万 |

这张表的系数是照候选的头一遍边界定的，所以它不能再拿头一遍去对；拿候选的第二遍边界（`mix-route-up`、`mix-route-down` 各再做一遍）去对，同时正式的驱动的配法也再做一遍，两种配法各两遍合在一起取每一档的最大值，再照 7-9 比。

- `holdout` 在候选上：三样负载合计要 3.4 个核心，不到 4 个，预计和正式的驱动的配法上量到的一样：转发每秒 6.38 万帧，路由器往 `wan` 1609 兆，主机往路由器每秒 6.94 万帧，路由器的口不发暂停帧；四个核心平均收包的线程 40%，发包的进程 32%，收"发完"的软中断 9%，别的线程 7.5%，空闲 8%。
- E-0006 判据 4-4 的负载在候选上（`fwdmix-*` 两张和原样重放六遍）：转发的 TCP 被千兆口的线速限住，预计转发的帧（数据加应答）每秒 10 万到 11.5 万，原样重放里"转发每 10 秒的速率"900 到 950 兆（E-0006 是 161 到 449）；路由器往 `wan` 实际发出 2300 到 2500 兆（正式的驱动的配法是 3950 到 4100）；`wan`、`lan2` 自己发的暂停帧比正式的驱动的配法少，但不是 0（收包的线程仍然要等正在跑的进程让出来）。依据是 `prio rx -20` 那一张 `knob` 里同一种负载的一窗（每秒 11.2 万帧，2394 兆）。
- E-0006 判据 4-7 头一半的负载在候选上：`jam` 表里"叫停多造成的损失"预计仍然是负的（叫停以后主机往 `wan` 发的变多），叫停前主机往 `wan` 每秒不少于正式的驱动的配法的 5.9 万到 6.6 万帧。原样重放里主机往 `wan` 开头 15 秒和后面的差多少，算不出来，只报数。
- `exp_rx_hardirq=1` 的边界：预计每一档都不比候选高（依据：它的 `knob` 里（1990 兆，每秒 13.3 万帧）那一窗，候选在同一档是 20 万上下）。

**7-10 重跑哪几条。** 候选只改了收包的线程的优先级，会碰到的、E-0006 里通过的是和"路由器自己往外发、口被压住"有关的两条：4-1（压住 `lan2` 25 秒，`pause` 阶段）和 4-3（路由器往 `wan` 发 64 条流三遍，`txrate`）。都在候选上用 E-0006 读数脚本的原阶段做，判法用 E-0006 报告里原来的。

## 3. 引导、路由器崩了的几次，和收工

### 3.1 内存引导

一共内存引导了 6 次：

| 第几次 | 启动号的头 8 位 | 为什么引导 |
|---|---|---|
| 1 | `3928ebd1` | 判据 7-1 的第一条路：串口上 `reboot` |
| 2 | `ee8f510d` | 7-1 的第二条路：往 `/proc/sysrq-trigger` 写 `c`，内核自己崩 |
| 3 | `d8b01a49` | 7-1 的第三条路：模块的 `stall` 让四个核心关着中断空转 90 秒，看门狗复位 |

## 5. 量到的东西

### 5.1 常数

芯片这一头：

- 叫停和放开的门限：`wan` 收进来的记账口占到 253 份叫停、降到 207 份放开；`lan2` 的是 250 和 209；"放开的门限"寄存器读到 214（上限 250 减 36）。门限随共用的那一组变小的式子没有量出来：两种慢法（每轮空等 500、2000 微秒）下共用的那一组最多用掉 250 份，门限没有动过。
- 一份缓冲：帧一交进收包环就还。收包环满了以后帧积在 PPE 里通主机的队列上（到过 272 到 288 份），记在收它的口的账上，到 250 份整个口叫停，不丢。
- 交货的上限只有下界：一个环每秒 86.8 万帧（驱动先到顶），四个环合计每秒 214.8 万帧（主机发到头）。
- 9014 字节的帧占 3 格；逐格找页 0 次。
- 中断延时寄存器写 0 到 4000 没有区别，都是一帧一个中断；它的单位和"发完"出现要多久没有量出来。
- 各个口进来的帧落到四个环：256 条流 20%、26%、26%、28%；32 条流每一遍不一样，最多的环到过 40%。

驱动和内核这一头（微秒）：

- 轮询函数里面：一轮收包固定的一份 7.59，每格连同补页 1.06（单独量：每格 0.84、每页 0.31），长帧后续的缓冲每格 0.15；一轮收"发完"固定的一份 2.19，每条 0.45 到 1.44（要还页的、本机 TCP 的贵），叫醒一条发送队列 3.69，把 5 个口扫一遍 0.056。
- 照每个核心忙的时间：转发一帧 3.52（`lan2` 进 `wan` 出）、8.96（`wan` 进 `lan2` 出）；收包的轮询每跑一轮固定的一份 43.3；收一条"发完"1.48；发一个本机的包 9.56；交给本机一帧 3.99。应答的单价没有量出来（16.5，标准误差 11.5）。
- 收包的线程被换下去以后最长等多久：只有转发时 0 到 4 毫秒；本机限速发送时 15 到 22 毫秒；本机不限速发送时 30 到 88 毫秒。
- 处理器的频率是自动调的；固定在最高和自动调，负载满的四窗没有差别（每秒 35.5 万帧对 35.6 万到 37.3 万；4777 兆对 4759 到 4766 兆）。

### 5.5 任务里列的九条线索

1. 两种配法"`wan` 实际发出、转发、重传"那张表：数照结果摘要重算对得上；口径确实不干净。同样的本机速率下比，收"发完"放进线程每一档都更差（5.2 小节）。
2. "`wan` 发了 20174 个暂停帧而 `wan` 收进来的那一格每次都读到 0"：每 3 秒采一次采不到。快读（一圈 2 微秒）量到触发的就是 `wan` 收进来的那一个记账口，占到 253 份叫停。
3. "流控的状态字"：低 11 位是这一刻放开的门限，第 16、17 位才是流控的状态；E-0004 到 E-0006 记到的 203、214、150 是门限那一栏。
4. `stage_fwdmix` 里本机那一组 `iperf3` 的输出没有读：属实。这一次两路都由模块在同一窗里数。
5. 4-7 的对照同时变了两样：属实。这一次的 `jam` 表两遍只差叫不叫停。
6. 换发完环的对法、核心匀了而速率没变：`exp_cmpl_shift=2` 的四窗里，只有本机发送时从 4759 兆掉到 3860 兆，转发加本机发送时本机是 3081 兆（两遍基线是 3463、3497）；没有一窗变快。
7. 每轮最多做到份额、回收完扫端口表、页对不上逐格找：代码属实；扫一遍 0.056 微秒，逐格找 0 次。
8. 线程和中断是不是逐个对在同一个核心：是，每一窗第 n 个收包环只在 n 号核心上轮询。
9. "本机 TCP 发下一批包有一大部分是被'发完'带着做的"：只有路由器往 `wan` 发时，四个核心合计 400% 里发包的进程 251% 到 266%，收"发完"的软中断 71% 到 72%，"发完"以后接着发的那一类软中断 11% 到 19%。接着发的这一部分占得不大，推论只成立一小半。
